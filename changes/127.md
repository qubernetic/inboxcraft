# 127

## Changelog
### Added
- Snooze: `mail.snooze` (`safe`, `until` or a preset of `schedule.presets`) puts a message in the account's own
  `InboxCraft/Snoozed` (made on the server the first time) until a time, in a new copy whose header carries the time
  in InboxCraft's own `InboxCraft-Snoozed-Until` field (replacing one an earlier snooze left); the old copy is deleted
  only once the server has the new one, and the copy is written only on a server that deletes one chosen message
  (UIDPLUS or IMAP4rev2, told by `net` after each sign-in), elsewhere the message is moved without the field (#127)
- At the time, `Session::tick` brings a snoozed message back to the inbox unread and marked as returned, listed as if
  it arrived then and told of as a notification; `mail.unsnooze` (`safe`) brings it back at once, and `history.undo`
  takes a snooze back (#127)
- A message that arrives in the snoozed folder with the field as its first header field, as another InboxCraft
  snoozed it, is snoozed until that time here too; the field further down counts for nothing (#127)
- `mail.list` says each row's `snoozed_until` and `returned` (#127)

## Roadmap
- Snooze: a copy with the time in our own header field in `InboxCraft/Snoozed`, back unread at the top at the time,
  read by a second InboxCraft, undoable (#127)

## Gaps
- Snooze writes its time into the server's copy only for a message whose body is kept, on a server with UID EXPUNGE
  (UIDPLUS or IMAP4rev2) that InboxCraft has signed in to since it started: elsewhere, and for a message whose move is
  still on its way, the message goes to the snoozed folder without the field, and another InboxCraft cannot tell when
  it comes back (it stays there until the owner moves it). A server with UIDPLUS that names no UID for the copy
  (UIDNOTSTICKY) gives it back from the folder's sync under a new id: its time is read from the field, but a park or
  a pin on it is lost. The copy goes up without the old one's arrival time (APPEND sends no date), so the server
  records it as received at the snooze, and the field stays in it after the return, an unsnooze or an undo. A copy the
  server refused leaves the message in its old folder with its time kept, and the time then only clears it. The
  returned mark stays until the message is snoozed again; the window shows it only while the message is unread
  (#135) (#127).
