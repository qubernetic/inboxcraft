# 127

## Changelog
### Added
- Snooze: `mail.snooze` (`safe`, `until` or a preset of `schedule.presets`) puts a message in the account's own
  `InboxCraft/Snoozed` (made on the server the first time) until a time, in a new copy whose header carries the time
  in InboxCraft's own `InboxCraft-Snoozed-Until` field; the old copy is deleted only once the server has the new one
  (#127)
- At the time, `Session::tick` brings a snoozed message back to the inbox unread and marked as returned, listed as if
  it arrived then and told of as a notification; `mail.unsnooze` (`safe`) brings it back at once, and `history.undo`
  takes a snooze back (#127)
- A message that arrives in the snoozed folder with the field, as another InboxCraft snoozed it, is snoozed until that
  time here too (#127)
- `mail.list` says each row's `snoozed_until` and `returned` (#127)

## Roadmap
- Snooze: a copy with the time in our own header field in `InboxCraft/Snoozed`, back unread at the top at the time,
  read by a second InboxCraft, undoable (#127)

## Gaps
- Snooze writes its time into the server's copy only for a message whose body is kept: one not downloaded yet, or
  whose move is still on its way, goes to the snoozed folder without the field, and another InboxCraft cannot tell
  when it comes back (it stays there until the owner moves it). On a server without UIDPLUS the copy comes back from
  the folder's sync under a new id: its time is read from the field, but a park or a pin on it is lost. A copy the
  server refused leaves the message in its old folder with its time kept, and the time then only clears it. The
  returned mark stays until the message is snoozed again, and the window has no snooze button, time picker or
  returned marker yet (the UI slice) (#127).
