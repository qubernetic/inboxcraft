# 137

## Changelog
### Added
- One InboxCraft at a time on the owner's mailbox: the first start holds `instance.lock` beside the store and
  listens on `instance.sock` (Unix, the owner's alone); a later start brings the running window forward and leaves,
  so two runs never open one store (#137)
- Closing the window leaves InboxCraft running without one: sync, rules and schedules go on, and a later start, the
  tray or the menu entry opens a new window on the same mailbox. `inboxcraft --background` starts without a window,
  `inboxcraft --quit` (and the menu entry's Quit action) ends the running one (#137)
- The tray on Linux: a StatusNotifierItem (`ksni`) with the unread count of every account's inbox in its tooltip;
  a click shows the window, its menu opens the window or quits (#137)
- Starting at login: `inboxcraft --autostart` and `--no-autostart` write or remove an XDG autostart entry that
  starts InboxCraft with `--background`; in the Flatpak they ask the Background portal, which each start also asks
  to let InboxCraft run without a window (#137)
### Changed
- The dev Flatpak may talk to the panel's StatusNotifierWatcher for the tray icon; its menu entry says there is one
  main window and has a Quit action (#137)

## Roadmap
- InboxCraft runs on with its window closed: one instance on the owner's mailbox, `--background`, `--quit`, the
  Linux tray with the unread count, and start at login through XDG autostart or the Background portal (#137)

## Gaps
- No tray outside Linux yet, and outside Unix no socket: on Windows a later start says that InboxCraft is already
  running instead of bringing its window forward, and closing the window ends InboxCraft, since nothing could bring
  it back. Start at login is XDG autostart and the Background portal only; Windows and macOS have none
  yet. A desktop without a StatusNotifierWatcher (GNOME without the AppIndicator extension) shows no tray icon:
  InboxCraft then runs on without a window all the same, and a start from the menu brings it back (#137).
- Without a window InboxCraft looks for the workers' events every half second rather than at once. A window opened
  again starts with egui's state fresh (scroll positions, open popups); the reader keeps the textures of the
  pictures it showed in the window before, whose ids mean nothing (or another picture) in the new one, so such a
  picture may be drawn wrong or not at all until `ui-egui` forgets them when a new window opens (#165). On Wayland
  a later start may only mark the running window as wanting attention rather than raise it, since no activation
  token is passed on (#137).
- The tray's tooltip counts the unread mail of every account's inbox; the icon itself carries no count yet, and its
  menu has no entries per account (#137).
