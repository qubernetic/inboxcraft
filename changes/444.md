# 444

## Changelog
### Added
- `calendar.import` (`owner`) adds the events of an `.ics` text, up to 5 MB and 5000 events, to one calendar, as
  `event.create` makes them under the file's own UIDs: a UID already there is skipped, each new event is a first
  write (`If-None-Match: *`), a preset repeat keeps its end and exceptions, another repeat stands once, a changed
  instance is left out, guests are not carried, a private or confidential event is private, and the whole import
  is one step of undo; the answer counts what was added, skipped, added once and refused, with reasons.
  `calendar.import.preview` (`safe`) says what it would do, changing nothing (#444)

## Roadmap
- `calendar.import`: events from an `.ics` file into one calendar, by UID, never overwriting (#444)

## Gaps
- `calendar.import` writes a repeat other than the presets (every second week, several rules, `RDATE`) as its first
  occurrence only, and leaves the changed instances of a series out; nothing in the window imports a file yet: an agent
  asks the owner to run it (#444).
- `calendar.import` writes a timed repeating event on this computer's wall clock, as `event.create` writes one, so a
  series from another zone (or in UTC) runs an hour off for the half of the year when the two clocks' summer time
  differs (#444).
- `calendar.import` does not carry an event's guests: an imported event has no guests. Its privacy is carried as
  `event.create` writes it: `CLASS:PRIVATE` and `CLASS:CONFIDENTIAL` are written as `PRIVATE`, any other class as
  none (#444).
- `calendar.import` refuses a file over 5 000 000 bytes or with more than 5000 events whole, rather than importing
  part of it (#444).
