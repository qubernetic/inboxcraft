# 444

## Changelog
### Added
- `calendar.import` (`owner`) adds the events of an `.ics` text, up to 5 MB and 5000 events, to one calendar, as
  `event.create` makes them under the file's own UIDs: a UID already there is skipped, each new event is a first
  write (`If-None-Match: *`), a preset repeat keeps its end and exceptions, another repeat stands once, a changed
  instance is left out, guests are not carried, and the whole import is one step of undo; the answer counts what was
  added, skipped, added once and refused, with reasons. `calendar.import.preview` (`safe`) says what it would do,
  changing nothing (#444)

## Gaps
- `calendar.import` writes a repeat other than the presets (every second week, several rules, `RDATE`) as its first
  occurrence only, and leaves the changed instances of a series out; nothing in the window imports a file yet, and an
  agent cannot ask the owner to run it yet (#444).
- `calendar.import` writes a timed repeating event on this computer's wall clock, as `event.create` writes one, so a
  series from another zone (or in UTC) runs an hour off for the half of the year when the two clocks' summer time
  differs (#444).
