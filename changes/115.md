# 115

## Changelog
### Added
- `proto` writes: UID STORE (`FlagStore`, with UNCHANGEDSINCE and the MODIFIED UIDs back), APPEND with APPENDUID
  (`AppendUid`; the message always goes as a literal after the go-ahead), CREATE, CLOSE and UNSELECT, with golden
  transcripts and the `imap_client` fuzz target driving them (#115)
- The IMAP write path in `net`: flags, move, delete for good (`\Deleted` and UID EXPUNGE of the job's messages
  only), APPEND and CREATE run on the server. A changed UIDVALIDITY writes nothing and is told; a message gone
  meanwhile is told as expunged after a store and named by no new UID after a move, not as a failure; CREATE of a
  folder that exists counts as made (#115)
- A write job that a dropped or timed-out connection cut off runs again after the reconnect, three times at most
  (`net::WRITE_TRIES`); writes queued offline run in order once the worker is online (#115)
- A live test of the write path in the run folder: APPEND, a flag, CREATE inside the run folder and a move there
  (#115)

## Roadmap
- The IMAP write path: flags, move, delete for good, APPEND and CREATE on the server, the offline queue run after
  the reconnect, a message gone meanwhile told as an event (#115)

## Gaps
- A write that a connection cut off runs again after the reconnect. APPEND cut off after the server took the message
  but before its answer adds it a second time (#115).
- A delete for good on a server without UIDPLUS (and not IMAP4rev2) fails before anything is sent, so the message
  stays: EXPUNGE there would remove every message marked `\Deleted`. A move on such a server leaves the moved
  messages in the old folder marked `\Deleted` (#115).
- `net` does not use UNCHANGEDSINCE yet: a flag the owner changes overwrites a change made on another device
  meanwhile (#115).
- `proto` takes an unclosed list at the end of a line (`* 1 FETCH (`) in an open mailbox as an empty FETCH instead
  of refusing it (#115).
