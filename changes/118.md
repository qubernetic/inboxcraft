# 118

## Changelog
### Added
- `inboxcraft-testkit` fake SMTP submission server, `testkit::smtp::FakeSmtp`, with its own command reader (never
  `proto`'s): EHLO and HELO, STARTTLS, AUTH PLAIN and AUTH LOGIN only over an encrypted connection (unless
  `auth_in_clear` makes it careless on purpose), MAIL FROM with SIZE, `BODY=8BITMIME` and SMTPUTF8, RCPT TO, DATA
  with dot-stuffing, RSET, NOOP and QUIT, enhanced status codes; extensions switchable per test; scripted refusals
  with their enhanced codes at the greeting, a command, one recipient or the message, and the faults of a script;
  every accepted message captured in its `Outbox`; a bounce script that drops an RFC 3464 delivery report into the
  fake IMAP server's mailbox through a `testkit::imap::Postbox`; implicit TLS and STARTTLS with the certificate
  faults, `Listen::start_smtp` and `Listen::start_smtp_many`; the fuzz target `testkit_smtp` (#118)

## Roadmap
- `testkit`: the fake SMTP submission server with its own command reader, scripted refusals with enhanced codes,
  captured messages, a bounce script into the fake IMAP mailbox, STARTTLS and implicit TLS with the certificate
  faults, fuzz target (#118)

## Gaps
- The fake SMTP server reads one command after the other, though it lists PIPELINING; it knows no CHUNKING,
  BINARYMIME, DSN parameters, XOAUTH2 or VRFY, and reads command lines up to 8192 bytes where RFC 5321 asks for 512.
  Its delivery reports carry a fixed date, quote the header block of the message as text even when it is not ASCII,
  and name one recipient each. A client idling on the fake IMAP server hears of a report only at its next command
  (#118).
