# 388

## Changelog
### Added
- The reader's More menu opens the original of an HTML message in the browser, on Linux: a cleaned copy of what the
  reader shows, with no script, no event handler and no address in it (a remote picture is a box with its words, a
  link its words), written to a file only the owner can read (`0600`, in a `0700` folder in the runtime folder, else
  the cache folder), named from the message's number alone, and handed to the desktop portal, or to `xdg-open`
  outside the Flatpak. A failure says why in the status line. The copies go at the next start, after ten minutes,
  and beyond sixteen. Only the owner's own press opens it: it is no command, so no agent, shortcut or palette can;
  the web app does not offer it (#388)

## Gaps
- The copy keeps no remote picture, even one the owner loaded for the message, and no link can be followed from it
  (#388).
- Under the portal, a desktop that has no browser for the file says so in its own way; the status line says only
  that the copy was handed on. Outside the Flatpak, `xdg-open` is waited for 0.8 s at most (#388).
- Only Linux opens the original; macOS and Windows do not offer the row (#388).
