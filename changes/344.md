# 344

## Changelog
### Added
- `event.list` names each event's `organizer` and says whether it is the owner's `own`: it names no organiser, or the
  organiser is the account's own address (#344)
- The event editor shows the event's description and keeps its lines; a press on a link in it with Ctrl (Cmd on a
  Mac) held copies the link, and the status line says so (#344)
- Someone else's event opens read-only in the event editor: every field read-only, the controls disabled, a note
  naming the organiser, and Close instead of Cancel and Save (#344)

## Gaps
- The full editor beside the day and the editor's own window are not built yet, so the "New event opens" setting
  (Small, Full or Window; Full by default, Edit following it) and the Alert field they draw wait for them: New event
  and Edit both open the small float (#344).
- The small editor lacks the frames' "more room" link over the description, the "also set" line (place and alert,
  which it does not show) and the two buttons that move the typing to the full editor or a window (#344).
- Links in the editor's description are not drawn as links (no cyan underline, no hand pointer, no target on hover);
  a press with Ctrl held copies one all the same (#344).
- A description longer than the 10 000 characters the calendar reads opens read-only in the editor, so the cut text
  never replaces the whole one (#344).
- `event.update` still changes someone else's event when an owner-class client asks; only the editor holds it
  read-only (#344).
