# 449

## Changelog
### Added
- "Unread only" in the mail list: a pill on the filters' line after "Show done" and the key `U` list only the
  unread messages of the view or folder shown. A row read meanwhile leaves at once; the open message stays open and
  keeps its row until you move on, so the next message is the next unread one. Each place keeps its own choice for
  the session (it is not saved); with nothing unread the list says "Nothing unread here." The command line lists it,
  and `ui.list.unread` (`safe`, `on` true, false or left out to turn it) asks the window for it (#449)
- `mail.list` takes `unread` (only the unread messages, counted so in `total` and paged so) and `keep` (one message
  kept in its place, read or not, while `unread` is on) (#449)

## Roadmap

## Gaps
- The design file draws no list with "Unread only": its pill follows the filters' line of
  `screen/inbox-list/show-done` (a 24 high `pill`, selected while on, 8 after "Show done") and its empty state the
  list's empty states (`screen/inbox-list/empty`); there is no frame to match it against (#449).
- "Unread only" filters the list of a place, not search results: while a search shows, the pill is not drawn and
  the results list read and unread mail (#449).
- The MCP tool `mail_list` does not take `unread` or `keep` yet; `mail.list` through the CLI and the control channel
  does (#449).
