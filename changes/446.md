# 446

## Changelog
### Added
- The window asks the owner about an agent's request for an `owner` command in a dialog over the dimmed window, in
  the app's own words: who asks (as the program calls itself), what would run and, for `calendar.import`, the
  calendar, how many events are added, skipped or left out, and the first five with their dates. It opens on Deny;
  `Esc` or a press on the dimmed window denies, and only the owner's press of "Allow once", from a second after that
  question showed, allows. The status line then says what the agent did, with Undo. While the window is not focused,
  is minimised or is closed, one desktop notification says the question, and a click on it brings the window forward
  (#446)

### Security
- The name a client gives itself over the control channel loses its format characters (bidi overrides and isolates,
  zero-width characters, separators) as well as its control characters, so it cannot turn round the owner's question
  (#446)

## Gaps
- The owner-request question has no frame in the FigCraft design file yet; the code draws it by the confirm dialog's
  rules (#446).
- Inside the question's “…” only plain characters are drawn (letters, numbers, punctuation and symbols; quote-like
  marks become one `'`, format characters are left out), but some ordinary letters and punctuation can still look
  like a double quote inside the data; a follow-up sets the data apart visually (#446).
- Without a window the owner-request question shows only as the desktop notification; when nobody opens the window
  from it and answers, the request times out (#446).
- Whether the desktop notification is shown is decided once, when a request comes to the front: when the window is
  focused then and the owner leaves it later, no notification follows (#446).
