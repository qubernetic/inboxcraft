# 117

## Changelog
### Added
- `proto::smtp`: a sans-I/O SMTP submission client (RFC 5321, RFC 6409) driven like the IMAP one (bytes in, bytes
  out, events): the greeting, EHLO, STARTTLS (sent EHLO again after it, bytes before the handshake refused), AUTH
  PLAIN and AUTH LOGIN, MAIL FROM with SIZE, `BODY=8BITMIME` and SMTPUTF8 each said only to a server that offers
  it, RCPT TO, DATA with every line ended in CRLF and dot-stuffed, RSET and QUIT; refusals carry their enhanced
  status code (RFC 3463) from a server that offers ENHANCEDSTATUSCODES. Reply lines, lines per reply and the
  extension list are capped; golden transcripts in `crates/proto/tests/transcripts/smtp/` and the fuzz target
  `smtp_client` (#117)
### Security
- The SMTP client refuses AUTH and MAIL until the connection is encrypted, hides the password and its base64 forms
  in a server's text, an error and `Debug` output, shows no server words before TLS, and refuses an EHLO domain or
  an address with a line break, a space, a control character, an invisible mark or an angle bracket (#117)

## Roadmap
- SMTP: the sans-I/O submission client in `proto` (EHLO, STARTTLS, AUTH PLAIN and LOGIN, MAIL, RCPT, DATA, SIZE,
  8BITMIME, SMTPUTF8, enhanced status codes), golden transcripts and a fuzz target (#117)

## Gaps
- The SMTP client sends one command at a time (no PIPELINING), has no CHUNKING or BINARYMIME, no DSN parameters, no
  HELO after a refused EHLO, and signs in only with AUTH PLAIN and AUTH LOGIN (no XOAUTH2 or OAUTHBEARER). It checks
  a message against the server's SIZE as given, before its line ends become CRLF and its lines are dot-stuffed.
  `net` does not drive it yet and the test kit has no fake SMTP server (#117).
