# 142

## Changelog
### Added
- The local control channel: the app on the owner's mailbox listens on a Unix socket in `$XDG_RUNTIME_DIR`
  (`inboxcraft/control.sock`, or the Flatpak's shared `app/<app id>/` folder), folder `0700` and socket `0600`, one
  JSON object a line each way (`docs/control-protocol.md`). Every line carries a token of 32 random bytes the app
  keeps in the OS credential store; a wrong, missing or revoked token is refused (`unauthorized`) and the connection
  closed. Only `safe` commands run, for an agent, in the window's session; at most eight clients, a line at most
  1 MiB (#142)
- `inboxcraft --revoke-control` puts a new token in the place of the old one; the app reads the credential store for
  every line, so the old token is refused from the next line on (#142)
- `inboxcraft-cli` without `--store` runs the command in the running app, and `inboxcraft-cli mcp` without `--store`
  runs its tools there, so the app runs the jobs they ask for; new error codes `not_running`, `no_token`,
  `unauthorized`, `busy`, `closing`, `bad_line`, `bad_answer` and `closed` (#142)
- `inboxcraft-control-key`: the token (constant-time comparison, never in `Debug` output), the request and answer
  lines with their limits, and the socket paths, shared by the app and the CLI; the fuzz target `control_lines` (#142)
- `inboxcraft_mcp::Commands`: the MCP server runs its tools on an engine session or on the running app (#142)
- `Mailbox::run_for_agent` in `ui-egui`: runs a command for an agent and reads the list again; an agent's act ends
  the window's Undo for the acts before it (#142)
### Changed
- `inboxcraft-cli` without `--store` no longer stops with a usage error: it looks for the running app (#142)

## Roadmap
- E2.7 part 2: the local control channel with a token in the credential store, revocable; the CLI and MCP talk to
  the running app when no `--store` is given (#142)

## Gaps
- The control channel is built on Unix only: on Windows the app runs without one and the CLI finds no app; `--store`
  works there. It does not check the client's process, so any process of the owner's that can read the credential
  store can use it. It has no approvals, so an `owner` command cannot be asked for over it. Without a window a call
  waits up to half a second for the app's next look (#142).
- An agent's act over the control channel ends the window's Undo for the owner's acts before it, rather than keeping
  both apart (#142).
